
## Текст для демо

**на странице аунтификации**

Сегодня демонстрируем вам плафторму ИИ Аналитик. В решении реализована ролевая модель пользователей, обеспечивающая сохранение персональных настроек интерфейса, прав доступа и истории взаимодействия в системой. 

**вводим логин пароль**

Вводим логин и пароль и переходим в настройки. Можно персонализировать приложение под свой вкус и потребности. Для администраторов так же доступно управление пользователей.

**переходим в рабочую область**

Перед началом работы выбираем источник данных. Источники данных сохраняются для каждого пользователя отдельно и переходят из сессии в сессию. Можно подключить постгрес, кликхаус или загрузить свои документы.

**выбираем источник данных**

В качестве примера я покажу работу системы на данных CSU компании ФПК. Пользователь вводит запрос обычным бизнес-языком, например: “Сравни пассажиропоток по филиалам”. Ему не нужно знать структуру базы данных, названия таблиц, колонок, SQL или внутренние инструменты системы.

**запускаем первый вопрос**

```
Проанализируй динамику пассажиропотока по филиалам ФПК за 2025 год. Выдели основные тенденции и филиалы с наиболее заметным ростом или снижением.
```

Под капотом система сначала определяет намерение пользователя: понимает, какой тип анализа нужен, какие бизнес-сущности упомянуты в запросе, какие показатели нужно посчитать и по каким разрезам их сравнить. 

Затем строится план анализа: определяется, к каким данным нужно обратиться, какие поля использовать, какие фильтры применить, какие агрегаты и формулы посчитать, какие проверки выполнить и в каком виде лучше вернуть результат.

После этого система вызывает необходимые инструменты: обращается к базе данных, формирует SQL запрос, извлекает необходимые данные и выполняет все расчеты.

Отдельный этап - верификация результата. Система проверяет корректность вычислений и формирует выводы искулючительно на основании данных из подключенного источника. При необходимости любой показатель можно проследить до исходны данных, использованный фильтров, сморфмированного sql запроса.

В результате пользователь получает готовый аналитический ответ в удобном виде: таблицы, графики, краткие выводы, сравнение сегментов, выявленные отклонения, инсайты и рекомендации для принятие управленческих решений.

## Демо семантического слоя: метрика успеха

Здесь вопросы не меняются: меняется только формула одной метрики в семантическом
каталоге. В каждом ответе агент должен назвать метрику и использованную формулу.

### Коэффициент `1000`

Для `fpk_monthly_success_metric` задаём формулу:

`passenger_count_actual / NULLIF(passenger_count_plan, 0) * 1000`

Задаём три вопроса:

1. `Покажи месячную метрику успеха ФПК за последний полный календарный год — с 1 января по 31 декабря — в таблице по месяцам.`
2. `Рассчитай годовую нормализованную метрику успеха ФПК за последний полный календарный год и покажи итог одной строкой.`
3. `Что такое КСОВ?`
4. *Добавить связанные сущности к терминам*
5. *Добавить вопрос по связям*

Проверяем, что месячные значения находятся примерно в диапазоне `989–1144`,
а годовая нормализованная метрика — около `87,78`. Формула годовой метрики:
`fpk_monthly_success_metric / 12`.

### Коэффициент `0.001`

Меняем только коэффициент той же месячной метрики:

`passenger_count_actual / NULLIF(passenger_count_plan, 0) * 0.001`

Повторяем те же три вопроса:

1. `Покажи месячные метрики успеха ФПК по месецам за `
2. `Рассчитай годовую нормализованную метрику успеха ФПК за последний полный календарный год и покажи итог одной строкой.`
3. `Что такое КСОВ?`

Проверяем, что месячные значения находятся примерно в диапазоне
`0.000989–0.001144`, а годовая нормализованная метрика — около `0.0000878`.
После теста возвращаем коэффициент месячной метрики `1000`.

Коэффициенты хранятся только в семантическом каталоге. Код, routing и prompts
между прогонами не меняются.
