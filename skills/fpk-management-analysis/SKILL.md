# Аналитика ФПК

Использовать этот скил как доменный контекст, а не как набор готовых ответов.
План и расчёт определяются текущим запросом, семантическим контрактом и
фактической схемой источника.

### Алгоритм

1. Определить источник по требуемому результату: табличные показатели получать
   из БД, документальные и нормативные сведения — через `rag_tool`.
2. Для многошагового анализа сформировать краткий рабочий план в основном цикле.
   Загружать `DETAILS.md` только когда конкретный пробел схемы не закрыт текущим контекстом.
3. Строить SQL по текущему вопросу и наблюдаемой схеме. Период, зерно, разрезы,
   рейтинг и формат результата брать из запроса, а не из заранее выбранного
   сценария. Использовать `pandas_tool` только для преобразования, которое
   нельзя завершить одним понятным SQL.
4. Формулу именованной производной метрики брать только из семантического слоя
   или из явного сообщения пользователя. Если формулы нет, запросить её. После
   расчёта привести использованное название метрики и формулу дословно.
5. Для прогноза использовать доступную в текущем runtime capability `forecast` и
   связанный с ней инструмент. Передавать полный упорядоченный временной ряд нужного
   зерна; план сравнения выбирать по тому же KPI и периоду. Не подменять внешний
   прогноз сохранённым `forecast` из исходной таблицы и не строить ручную
   экстраполяцию.
6. После получения достаточных артефактов сразу сформировать ответ в запрошенном
   формате. Не выполнять повторные проверки уже рассчитанных значений.

### Карта источников

- `demo_fpk.stat_stats` — дневные показатели перевозок; `structure='ФПК'` задаёт
  итог компании, `metric` — сценарий, `sys_section` — временное зерно.
  `seat_turnover` — оборот мест и только прокси операционной загрузки, не
  коэффициент занятости мест.
- `demo_fpk.stat_csi` — помесячные компоненты CSI, удовлетворённость и лояльность.
- `demo_fpk.stat_isoo` — обращения пассажиров: `тематика_обращения` задаёт тему,
  `шифр` — код темы, а филиалы представлены отдельными числовыми колонками.
  Для филиального результата разворачивать эти колонки; не соединять `шифр` с
  идентификатором филиала.
- `demo_fpk.stat_manual` — длинная таблица KPI уровня ФПК; `metric` разделяет
  `plan`, `fact` и сохранённый `forecast`, `value_name` выбирает KPI, а `value`
  содержит его числовое значение. Для пассажиропотока использовать
  `value_name='pass_count'`; для помесячного сравнения — `sys_section='month'`.

### Правила

- Для табличной аналитики использовать только `demo_fpk.stat_stats`,
  `demo_fpk.stat_csi`, `demo_fpk.stat_isoo`, `demo_fpk.stat_manual`.
- Считать `ФПК` итогом компании, а не филиалом; не смешивать итог с филиалами и
  исключать его из рейтингов филиалов.
- Не смешивать взаимоисключающие `plan`, `fact`, `forecast` и разные значения
  `sys_section` в одном агрегате.
- Учитывать различия зерна, единиц и обозначений филиалов между таблицами.
- Называть корреляцию наблюдаемой связью, а не причиной.
- После ошибки или пустого результата проверить подключение, схему, значения
  фильтров и период до следующего расчёта.
- Перед финальным ответом убедиться, что каждое названное число присутствует в
  артефакте инструмента.

## Формат ответа

Дать краткий вывод, требуемую таблицу или график, тенденции и ограничения. Для
рекомендаций отделять наблюдаемую проблему от предлагаемого действия и KPI.
