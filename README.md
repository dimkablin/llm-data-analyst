# LLM Data Analyst

Интерактивная платформа для анализа данных на естественном языке. Пользователь
подключает данные, задаёт вопрос, а система возвращает проверяемый ответ:
текстовое объяснение, таблицы, графики, метрики и историю агентных шагов.

Проект развивается как доменно-нейтральная среда выполнения LangGraph/ReAct
поверх FastAPI и React. Бизнес-вертикали подключаются через навыки,
типизированные инструменты, Pydantic-контракты, права доступа и доменные
расширения MCP, а не через клиентские ветки внутри агентного исполнителя.

---

## Возможности

- **Доменно-нейтральная среда выполнения LangGraph** — компактный граф
  `prepare_context → agent → finalize`, типизированное состояние, события
  выполнения, ссылки на артефакты и сборка финального ответа.
- **Тонкий FastAPI слой** — маршруты делегируют выполнение в
  `QueryExecutionService`, который отвечает за аутентификацию, проверку
  владельца, настройки, источники, потоковую отдачу, сохранение состояния и
  стабильные API-контракты.
- **Структурированные инструменты** — pandas, Plotly, SQL/DuckDB, внешние БД,
  RAG, поиск, прогнозирование, план-факт аномалии, память и проверка ответа
  работают как типизированные инструменты со строгими входами, выходами и
  правами доступа.
- **Доменные расширения** — инвестиции, продажи, риск, прогнозирование и
  другие вертикали добавляются через навыки в разметке, Pydantic-схемы, доменные
  манифесты и MCP-адаптеры.
- **Рабочая область React** — чат, доска артефактов, настройки модели,
  источники данных, сессии и трассировка доступны в одном контуре фронтенда.
- **SSE и наблюдаемость** — токены, ход рассуждения, события инструментов,
  фазы, граф выполнения и финальная полезная нагрузка идут потоком в UI и
  трассируются через
  Arize Phoenix.
- **Экспорт и артефакты** — HTML-отчёты, Plotly-графики, таблицы, значения и
  заметки можно закреплять на доске и переиспользовать в сессии.

## Архитектура

Актуальная архитектура строится вокруг явных границ ответственности:

- **Среда выполнения LangGraph** выполняет только обобщённый агентный цикл:
  типизированное состояние, узлы графа, маршрутизацию, вызовы LLM,
  оркестрацию инструментов, права доступа, события, артефакты и финализацию
  ответа.
- **Продуктовый слой бэкенда** держит FastAPI, аутентификацию, сессии,
  хранилище, управление источниками, API-схемы, сохранение состояния,
  наблюдаемость и сервисные интерфейсы.
- **Пользовательский слой фронтенда** отвечает за сценарии пользователя,
  настройки, представление артефактов и типизированное потребление API.
- **Слой доменных расширений** добавляет вертикальную экспертизу через
  MCP-серверы, типизированные инструменты, Pydantic-схемы, права доступа и
  навыки в разметке.

```text
React фронтенд
    -> маршруты FastAPI
    -> QueryExecutionService
    -> AgentRunner
    -> LangGraph: prepare_context -> agent -> finalize
    -> типизированные инструменты / навыки / доменные манифесты / MCP-адаптеры
```

## Быстрый старт (Docker)

```bash
cp .env.example .env
# Отредактируйте .env: LLM-адрес, секреты входа, хранилище, порты.

docker compose up --build -d
```

Единая точка входа — **фронтенд/nginx**, который проксирует API-запросы к
бэкенду и Phoenix:

| Сервис | URL |
|--------|-----|
| Приложение | `http://localhost:${FRONTEND_PORT}` |
| Phoenix UI | `http://localhost:${FRONTEND_PORT}/phoenix/` |

Бэкенд не выставлен наружу и доступен только через nginx во внутренней сети
Docker.

### Обратный прокси / Scibox

Если приложение публикуется не из корня домена, а под префиксом, задайте
`APP_BASE_PATH`.

```bash
APP_BASE_PATH=/scibox/llm-data-analyst/
```

Тот же префикс должен использоваться:

- при сборке образа фронтенда: `--build-arg APP_BASE_PATH=...`
- в окружении выполнения контейнера фронтенда: `APP_BASE_PATH=...`

Тогда SPA-маршруты, ресурсы фронтенда, прокси-маршруты API и `/phoenix/`
будут работать под одним базовым путём.

### Порты

| Переменная | По умолчанию | Внутренний порт |
|------------|--------------|-----------------|
| `FRONTEND_PORT` | 8603 | 8603 |
| `PHOENIX_UI_PORT` | 6006 | 6006 |
| `PHOENIX_GRPC_PORT` | 4317 | 4317 |

## Локальная разработка

```bash
# Зависимости Python
poetry install

# Бэкенд
poetry run uvicorn backend.api.app:app --host 0.0.0.0 --port ${BACKEND_PORT:-8000} --reload

# Фронтенд
cd frontend
npm install
npm run dev
```

Сервер разработки Vite проксирует API-запросы к бэкенду через
`frontend/vite.config.ts`.

## API

| Метод | Путь | Назначение |
|-------|------|------------|
| POST | `/auth/register` | Регистрация |
| POST | `/auth/login` | Авторизация |
| GET | `/auth/me` | Текущий пользователь |
| GET/PATCH | `/auth/settings` | Пользовательские настройки модели и анализа |
| POST | `/sessions` | Создать сессию |
| GET | `/sessions` | Список сессий |
| GET | `/sessions/{id}` | Состояние сессии: история, источники, артефакты |
| POST | `/sessions/{id}/data` | Загрузить табличные данные |
| POST | `/sessions/{id}/query` | Синхронный запрос |
| POST | `/sessions/{id}/query/stream` | SSE: токены, рассуждение, инструменты, фазы, финальная нагрузка |
| GET/POST/PATCH/DELETE | `/admin/users` | Управление пользователями |

## Конфигурация

Полный список переменных — в [.env.example](./.env.example).

Ключевые группы:

- **LLM** — провайдер, модель, OpenAI-совместимый URL, температуры, лимиты
  токенов, режим рассуждения.
- **Агент и среда выполнения** — максимум шагов, таймауты, кеш, глубина
  анализа, политика инструментов.
- **Бэкенд** — TTL сессий, лимиты файлов, CORS, пути хранилища.
- **Вход** — путь к БД, TTL токена, настройки начального администратора.
- **Phoenix** — адрес коллектора, имя проекта, флаги инструментирования.
- **Интеграции** — поиск, RAG, MCP, БД и настройки внешних сервисов.
