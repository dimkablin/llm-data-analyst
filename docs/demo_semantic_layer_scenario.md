# Демонстрация семантического слоя: PostgreSQL и CSV

## Назначение

Это один сценарий на 10–15 минут в двух взаимозаменяемых вариантах. На живом
показе выбирается один вариант, а не проходят оба подряд.

- Вариант A — PostgreSQL: показать подключение к БД и семантику поверх схемы.
- Вариант B — CSV: показать тот же финансовый план без внешней БД.

Оба варианта используют один набор из четырёх вопросов и дают одинаковые
контрольные результаты. Новые данные, инфраструктура, UI и продуктовый код не
нужны.

## Подготовка и параметры

### Вариант A: PostgreSQL

Используются существующие docker-compose.demo-dbs.yaml и схема demo.

Проверенный запуск на этой Windows-машине:

    $env:DEMO_POSTGRES_PORT = '55460'
    docker compose -f docker-compose.demo-dbs.yaml up -d demo_postgres
    docker compose -f docker-compose.demo-dbs.yaml ps demo_postgres

| Backend | Host | Port | Database | User | Password | Schema |
|---|---|---:|---|---|---|---|
| Локальный | localhost | 55460 | demo_analytics | demo | demo | demo |
| В той же Docker-сети | demo_postgres | 5432 | demo_analytics | demo | demo | demo |

Compose по умолчанию предлагает 55432, но на проверенной машине порт входит в
исключённый диапазон TCP 55352–55451. Используйте предусмотренную переменную
DEMO_POSTGRES_PORT=55460. Healthcheck и TCP-подключение к localhost:55460
прошли.

| Таблица | Строк | Колонок | Использование |
|---|---:|---:|---|
| demo.manual_plan | 138 | 68 | Основной факт плана P&L/CF |
| demo.uh_receipts_2026_03 | 1 068 | 30 | Только обзор, не используется в вопросах |

Ключевые типы: в manual_plan колонки pl_jan и pl_fy имеют тип numeric; в
uh_receipts_2026_03 дата_документа имеет text, сумма — numeric.

Связь между таблицами не создаётся. В manual_plan заполненных значений
контрагент — 0 из 138; в uh_receipts_2026_03 — 601 строка / 237 различных
значений; пересечение множеств равно 0. Ограничений PK/FK в схеме demo нет.
Поэтому пустая вкладка «Связи» — правильный безопасный результат, не ошибка.

### Вариант B: CSV

Используется существующий файл:

    demo_dbs/data/manual_plan.csv

| Проверка | Фактический результат |
|---|---|
| Кодировка | UTF-8 без BOM, декодируется без ошибок |
| Разделитель и заголовок | запятая, первая строка, 68 заголовков |
| Данные | 138 строк, в каждой 68 полей |
| Пустые значения | пустых ячеек нет; есть строковый маркер \N |
| Типы после batch-загрузки | pl_jan, pl_feb, pl_mar, pl_fy — DOUBLE |
| Приложение | batch API создал таблицу manual_plan, 138 × 68 |

Маркер \N в CSV-пути остаётся строкой, а инициализация PostgreSQL трактует его
как NULL. Основные вопросы не фильтруют эти текстовые поля, а все нужные
PL-колонки распознаны числовыми, поэтому файл стабилен для данного сценария.
Не показывайте на нём анализ пропусков.

Не используйте demo_dbs/data/uh_receipts_2026_03.csv как CSV-источник: из-за
\N поле сумма в CSV-пути распознаётся как VARCHAR.

Проверены examples/semantic-demo/orders.csv (4 × 5) и customers.csv (3 × 4):
у них подтверждённая безопасная связь orders.customer_id → customers.customer_id.
Они не выбраны, чтобы не менять финансовый сюжет и вопросы.

## Путь в приложении

1. Создать новую сессию.
2. A: в «Подключения к БД» создать PostgreSQL connection с параметрами выше,
   выбрать схему demo, нажать «Тест», затем «Использовать».
3. B: в «Загрузки CSV/XLSX» нажать «Загрузить CSV/XLSX», выбрать
   demo_dbs/data/manual_plan.csv и подтвердить «Загрузить».
4. Открыть настройки сессии → «Метаданные / Семантический слой».
5. Нажать «Сгенерировать семантический слой» и дождаться ready.

В A обзор содержит demo.manual_plan и demo.uh_receipts_2026_03; в вопросах
используется только manual_plan. В B будет одна таблица manual_plan. Текущий UI
задаёт схему подключения, но не хранит постоянный список выбранных таблиц; не
изображайте такую настройку.

Покажите вкладки:

- «Обзор»: цфо, статья_pl, pl_jan, pl_feb, pl_mar, pl_fy.
- «Метрики»: кандидаты на суммы PL/CF.
- «Термины»: бизнес-словарь.
- «Связи»: пусто, потому что ключ не доказан.

Точный перечень AI-объектов зависит от модели. Добавьте или отредактируйте
вручную один термин на вкладке «Термины»:

| Поле | Значение |
|---|---|
| Термин | План P&L |
| Определение | Годовой план доходов и расходов из строк manual_plan. |
| Синонимы | бюджет, план доходов и расходов |
| Связанные сущности | оставить пустым |

Так запрос со словом «бюджет», которого нет в колонках, становится
воспроизводимым.

## Fallback без LLM

До демо один раз сгенерируйте каталог на том же пользователе и источнике и
проверьте ready: каталог сохраняется для того же источника. Если генерация
недоступна, нажмите «Обновить» — таблицы и колонки будут построены без LLM —
и вручную добавьте метрики ниже. Поле «Измерения» оставьте пустым.

| Key | Название | Тип | Таблица A / B | Expr или formula |
|---|---|---|---|---|
| plan_pl_jan | План P&L за январь | simple, sum | demo.manual_plan / manual_plan | pl_jan |
| plan_pl_feb | План P&L за февраль | simple, sum | аналогично | pl_feb |
| plan_pl_mar | План P&L за март | simple, sum | аналогично | pl_mar |
| plan_pl_year | Годовой план P&L | simple, sum | аналогично | pl_fy |
| plan_pl_q1 | План P&L за I квартал | derived | аналогично | plan_pl_jan + plan_pl_feb + plan_pl_mar |
| plan_pl_q1_share_pct | Доля плана P&L за I квартал | derived | аналогично | plan_pl_q1 / NULLIF(plan_pl_year, 0) * 100 |

Затем добавьте термин «План P&L» из предыдущей таблицы. Ручное сохранение всех
шести метрик и термина проверено через текущий SemanticCatalogService без LLM:
статус каталога ready.

## Четыре основных вопроса

Relationships для всех четырёх вопросов: **нет**. Обе ветки используют одну таблицу plan; для PostgreSQL связь с receipts не подтверждена, для CSV второй таблицы нет.

Валюты в источнике нет. Называйте суммы «денежными единицами источника», а не
рублями. Все результаты ниже независимо рассчитаны и совпали в PostgreSQL и
в сессионном DuckDB после фактической batch-загрузки CSV.

Для PostgreSQL используйте SQL ниже. Для CSV выполните тот же SQL через
существующий GET /csv/query с session_id и URL-кодированным sql, либо напрямую
в сессионном DuckDB, заменив demo."manual_plan" на manual_plan.

### 1. Простая агрегация

Точный текст в чат: «Какова общая сумма плана P&L за январь?»

| Поле | Значение |
|---|---|
| Источник | PostgreSQL или CSV |
| Нужные объекты | plan_pl_jan; таблица manual_plan |
| Ожидаемая форма | одно число и пояснение, что это сумма 138 строк |
| Контроль | 127 638 655,89 денежных единиц источника |

    SELECT ROUND(SUM("pl_jan"), 2) AS january_plan
    FROM demo."manual_plan";

### 2. Термин / синоним

Точный текст в чат: «Какой годовой бюджет P&L?»

| Поле | Значение |
|---|---|
| Источник | PostgreSQL или CSV |
| Нужные объекты | термин План P&L с синонимом бюджет; plan_pl_year |
| Ожидаемая форма | одно число с расшифровкой «годовой план P&L» |
| Контроль | 1 611 960 931,69 денежных единиц источника |

    SELECT ROUND(SUM("pl_fy"), 2) AS annual_plan
    FROM demo."manual_plan";

### 3. Бизнес-измерение

Точный текст в чат: «Покажи три крупнейших ЦФО по годовому плану P&L.»

| Поле | Значение |
|---|---|
| Источник | PostgreSQL или CSV |
| Нужные объекты | измерение цфо; plan_pl_year |
| Ожидаемая форма | таблица из трёх строк, сортировка по убыванию |

| ЦФО | Годовой план |
|---|---:|
| Департамент процессинга | 806 391 359,52 |
| Финансовый отдел_Мультикарта | 265 475 151,61 |
| Департамент развития технологий | 198 263 731,90 |

    SELECT "цфо", ROUND(SUM("pl_fy"), 2) AS annual_plan
    FROM demo."manual_plan"
    GROUP BY "цфо"
    ORDER BY annual_plan DESC, "цфо"
    LIMIT 3;

### 4. Вычисляемая метрика по периодам

Точный текст в чат: «Какова доля плана P&L за I квартал в годовом плане P&L?»

| Поле | Значение |
|---|---|
| Источник | PostgreSQL или CSV |
| Нужные объекты | месячные PL-метрики, plan_pl_year, plan_pl_q1_share_pct |
| Ожидаемая форма | формула, сумма I квартала, годовая сумма, процент; не среднее процентов строк |
| Контроль | 391 033 362,07 / 1 611 960 931,69 = 24,2582 % |

    SELECT
      ROUND(SUM("pl_jan" + "pl_feb" + "pl_mar"), 2) AS q1_plan,
      ROUND(SUM("pl_fy"), 2) AS annual_plan,
      ROUND(SUM("pl_jan" + "pl_feb" + "pl_mar")
        / NULLIF(SUM("pl_fy"), 0) * 100, 4) AS q1_share_pct
    FROM demo."manual_plan";

## Два запасных вопроса

1. Точный текст: «Сколько строк содержит план P&L?»
   Источник: PostgreSQL или CSV. Контроль: **138**.
   SQL: SELECT COUNT(*) FROM demo."manual_plan";

2. Точный текст: «Какой ЦФО имеет максимальный годовой бюджет P&L?»
   Источник: PostgreSQL или CSV. Нужны цфо, plan_pl_year и синоним «бюджет».
   Контроль: **Департамент процессинга — 806 391 359,52**.

## Сброс и troubleshooting

### Сброс demo-данных

    docker compose -f docker-compose.demo-dbs.yaml down -v
    $env:DEMO_POSTGRES_PORT = '55460'
    docker compose -f docker-compose.demo-dbs.yaml up -d demo_postgres

Команда down -v удаляет только именованные demo-volumes этого compose-файла,
включая ClickHouse demo-volume, если он запускался; основной compose проекта
она не затрагивает.

### Три вероятные проблемы

1. **Порт 55432 недоступен.** Использовать DEMO_POSTGRES_PORT=55460 и
   localhost:55460.
2. **LLM остаётся в indexing или failed.** Это зависимость от провайдера, не от
   источника. Перейти к сохранённому каталогу или ручному fallback.
3. **CSV не даёт 138 × 68 или PL стал текстом.** Загрузить исходный
   demo_dbs/data/manual_plan.csv, не пересохранять его в Excel и не заменять
   на uh_receipts_2026_03.csv.
